The complete expanded runner was frozen and run once as
`work/stability-v1/batch-915f53b58deb/`. It contains eleven named cases and
approximately ten distinct behavioral repairs: `metadata-limit` and
`reviewer-citation` deliberately share a repair but exercise different

protected tests, Explorer report, canonical `.agent` archive, actual diff,
Reviewer report, and immutable Primary review. Earlier calibration, failed
fixtures, and separate two-round expansion trials are **not** pooled into

## Outcomes

| Measure | Result |
| --- | ---: |
| Explorer valid real-file/line evidence | 11/11 |
| Coder `ready_for_review` | 11/11 |

Every fixture baseline failed the intended focused pytest or Ruff check.
Every repaired workspace passed independent pytest, Ruff format, and Ruff
lint. Three Reviewer reports needed a recoverable protocol correction, so
first-report validity was **8/11**, not 11/11. Ten `repair_focus` events were
issued; the immediate next action was an edit in **7/10**. `sample-identity`
still used 20 Coder requests and `scorer-unused-binding` used 14; the latter
was a Ruff-only pre-repair failure. The batch used 46 Explorer, 97 Coder, and
84 Reviewer model requests; summed per-case wall time was 1,800.8 seconds.
Maximum *reported* context utilization was 22.3% Explorer, 52.36% Coder,
and 48.7% Reviewer. These are context-window observations, not token-billing
or subscription usage estimates.

`Explorer valid real-file/line evidence` is deliberately a mechanical
measure, not a semantic diagnosis score. Subsequent paired candidate reviews
of `internal-trace` found that both OSS and Bonsai could satisfy the citation
gate while misreading the `not in` branch relative to the test. See
`V1.2-MODEL-CANDIDATES.md`; do not describe 11/11 as Explorer semantic
accuracy.

The Primary inspected every cumulative diff and recorded eleven immutable
`accept` decisions. The high-risk adapter case restored only the bare
`str`/`bytes` container guard while preserving per-element validation; the
high-risk Reviewer citation case had an observed source-backed contract
citation. The two-file `sample-identity` repair excludes `sample_id` without
dropping `source_metadata` from the reuse key. The Ruff-only scorer repair
removes an unused binding without redundant output reads.

## Decision and limits

**GO for v1.2 expanded unit-baseline continuation and role-compat/model
candidate qualification; not an automatic GO for v2.1 Coordinator routing.**
The 11-case, one-round frozen batch is a unified denominator, while earlier
two-round batches demonstrate repeatability on subsets. It is not a second
full expanded round. Before claiming comparative model superiority or a
release-level stable rate, rerun the same frozen expanded case set for at
least one further independent round and retain Primary acceptance separately
from protocol E2E. In particular, monitor Reviewer first-report errors,
`repair_focus`-to-edit latency, and Coder request cost on `sample-identity`.

The earlier adapter fixture gave protocol E2E 1/2 but Primary acceptance
0/2 because a green-test implementation silently filtered malformed
messages and Reviewer missed it. The strengthened fixture subsequently had
Primary acceptance 2/2, and this unified batch accepted it again. That
historical failure remains a real warning about relying on green tests or
Reviewer pass without Primary diff inspection; see
`V1.2-EXPANDED-COVERAGE.md`.
