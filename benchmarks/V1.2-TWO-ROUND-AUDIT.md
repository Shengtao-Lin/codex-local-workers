## Proactive repair-context experiment (2026-09-27)

The immutable 22-cell batch showed that eight of its nine non-immediate
post-`repair_focus` actions were repeated READ/SEARCH attempts rejected by the
existing one-shot gate. The runtime now supplies its existing current-hash,
source-backed compact repair context immediately after a failed `VALIDATE`
when it has an editable source excerpt. It still permits a bounded read that
actually yields new evidence. A three-case pilot in
`work/stability-v1/batch-9c8b6f72e13a/` reached 3/3 E2E and 2/3 immediate
edits; Primary reviewed all three actual diffs and recorded acceptance.

A preselected five-case, two-round trial in
`work/stability-v1/batch-15c04d7e91c1/` is the substantive check. It yielded
8/10 first-repair immediate edits and 8/10 E2E passes, with 0/10 infra
failures. Explorer produced 9/10 mechanically valid reports, Coder passed
8/10, and Reviewer passed all eight reached units. Primary reviewed and
accepted the eight passing diffs. **Both** `sample-identity` rounds failed
Coder validation. In one, a manually reconstructed sample payload introduced
nonexistent `sample.effective_config`; in the other, `sample_id` was removed
from the nested sample but added back at the payload top level. Primary
recorded takeover for both. The trial is diagnostic, not pooled with the
original 22-cell baseline, and it does not qualify v1.2 release.

The runner now records the *first* repair's next action separately; the
readiness report reconstructs that action from immutable events for older
archives, rather than treating any later immediate edit in the same unit as
success. Its historical result remains 12/21. A general repair-focus rule
also redirects an `AttributeError` ending in third-party code to a newly
introduced missing-attribute access in an authorized changed source file,
provided the access is absent from that file's preimage. A single changed-
approach `sample-identity` replay in `work/stability-v1/batch-61121d64d2d5/`
used that focus for the missing `effective_config`, but Coder introduced
another nonexistent `sample.scorer` and failed again. Primary recorded
takeover; do not repeat the same Qwen packet or raise its turn budget.

The proactive context change is retained as an **action-convergence
improvement only**. It does not establish semantic repair convergence:
two-file `sample-identity` failed 3/3 consecutive post-change calls. The
current OSS/Qwen/Muse mapping and Phase 2 **NO-GO** remain unchanged. The
scoped regression suite is 291 passed plus 4 subtests, with Ruff clean.

Post-audit inspection found that the first proactive implementation replaced
the model's prior message history after failed validation. In the failed
two-file calls, that discarded an earlier read of `CanonicalSample` fields,
plausibly contributing to invented field accesses. The current code appends
the repair payload while preserving earlier source observations; the later
one-shot no-evidence nudge remains the compacting boundary. A regression
test proves preservation, but this amended behavior has **not** passed a
fresh two-round E2E. The 8/10 figures above describe the archived first
implementation, not the amended one.
After the amendment and offline Coordinator state tests, the scoped suite is
293 passed plus 4 subtests, with Ruff clean.

## Bounded prior-read restoration (2026-09-27)

Inspection of the final failed `sample-identity` trace found a narrower runtime
issue: Coder had already read the `CanonicalSample` definition, then requested
it again after a failed validation. The duplicate read was correctly rejected,
but the one-shot repair-context compaction discarded that prior model definition
and supplied only editable-file excerpts. The nudge now restores up to 80
already-observed lines from the attempted duplicate read, only when the file
hash is still current. This is explicitly zero new evidence, does not increase
read or repair budgets, and grants no new writable scope. Unit and integration
tests cover restoration and changed-hash refusal.

A separate two-case/two-round regression in
`work/stability-v1/batch-a28f281e8926/` used the active OSS/Qwen/Muse mapping.
All 4/4 cells had mechanical Explorer evidence, Coder `ready_for_review`,
Reviewer `pass_to_primary`, independent pytest/Ruff passes, and Primary acceptance
after actual diff review; all four first repair actions were edits and there
were no infrastructure failures. Its maximum *reported* context utilization
was below 47% for Coder. No cell entered the duplicate-read nudge branch, so
this is a no-regression check, **not** evidence that the new restoration improves
`sample-identity` conversion or Explorer strict semantic diagnosis. The full
scoped suite is 295 passed plus 4 subtests. Current Phase 2 decision remains
**NO-GO**; the three prior Qwen `sample-identity` failures are not reset by
these different units.

## Remove test-name-derived repair constraints (2026-09-27)

The repair context previously parsed words after `ignores_` and `preserves_`
in test names into global `must_ignore` and `must_preserve` fields, then called
those inferred lists hard constraints. This conflicted with the frozen
`sample-identity` packet: `row_identity` is a test concept rather than a model
field, and `source_metadata` must be ignored by `content_fingerprint` while
remaining in `score_reuse_key`. The runtime now uses the packet's required
behaviors and scenarios for semantics. Validation history still identifies
tests already passing or resolved, without inferring field rules from names.

After this change, the active OSS/Qwen/Muse mapping passed the copied two-file
`sample-identity` case in both rounds of
`work/stability-v1/batch-e1cb57ed0142/`: Coder `ready_for_review` 2/2,
Reviewer `pass_to_primary` 2/2, independent six-test pytest and Ruff 2/2,
and Primary accepted both actual two-file diffs. Both Explorer reports had
real file/line evidence; Primary judged round one incomplete on the
`score_reuse_key` `sample_id` assertion and round two complete. Both Coder
runs used the bounded prior-read restoration once and eventually edited and
validated. In both, the first action after `repair_focus` was a redundant
read, so immediate-edit conversion was 0/2. No infrastructure failure or
context-window pressure was observed (maximum reported Coder context use
53.47%).

This is a changed-runtime diagnostic, not a replacement for the frozen
22-cell baseline. It supports renewed two-file Coder conversion, but does
not isolate the relative contribution of the repair-context and
test-name-inference changes. Explorer strict diagnosis and immediate-edit
rate remain release blockers. The full scoped suite is 295 passed plus four
subtests; Phase 2 remains **NO-GO** pending a new frozen expanded repeat and
the other v1.2 gates.
