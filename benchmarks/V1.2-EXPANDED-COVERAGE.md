## Model portability boundary

The role runtimes dispatch by configured model ID and role capabilities;
they have no hard-coded `oss`, `qwen`, or `muse` behavior branch. They are
still coupled to an OpenAI-compatible LM Studio endpoint and require a
working context length, output format, and tool-call behavior for each
candidate model. `role_compat.py` is therefore the gate before semantic
model A/B testing. This follow-up did not qualify or switch an alternative
model, so it makes no claim that another model is equally reliable.

After these changes, the combined repository/local-agent regression suite
passed **233 tests and 4 subtests**. The next broader sample should add
more distinct real repository behaviors, keep Primary acceptance separate
from protocol E2E, and include a Reviewer finding case whose contract is
explicit but focused tests intentionally miss the defect.

## Wider positive unit sample

The runner contains eleven named cases. `metadata-limit` and
`reviewer-citation` intentionally exercise the same underlying repair with
different risk/citation obligations, so this is approximately **ten distinct
behavioral units**, not eleven independent bug types. The original six-case
baseline remains immutable. Four additional positive behaviors were added:
percentage sampling scale, metadata key-length boundary, zero-seed random
selection, and adapter message-sequence shape. The first three were run in two
separate three-case batches, `batch-281ece63ff0e/` and
`batch-c83a6dc1a72c/`. Across those six independent snapshots, Explorer
evidence 6/6, Coder ready 6/6, valid Reviewer reports 6/6, protocol E2E
6/6, and infrastructure failures 0. Primary inspected every actual diff and
recorded six immutable `accept` decisions. These are expansion trials, **not
a single rerun of all ten distinct behaviors under one frozen runner hash**.

The adapter case exposed a useful negative result. Its first two snapshots,
`batch-c98f05563b47/`, had Explorer 2/2, Coder ready 1/2, valid Reviewer
report 1/1 reached, and protocol E2E 1/2. Primary acceptance was **0/2**:
one Coder call failed after filtering messages and malformed edit attempts;
the other made tests green by filtering invalid elements out of the sequence.
Reviewer passed that second diff, but Primary detected the silent data loss
and recorded `rework` for both runs. This was an acceptance-test and Reviewer
coverage gap, not an infrastructure failure. Those records remain unchanged.

The revised fixture protects the mixed valid/invalid element path, explicitly
requires every element to be validated without filtering, and classifies the
public adapter boundary as high risk. In `batch-4dbee20bed0e/`, both fresh
rounds had Explorer evidence, Coder ready, source-cited high-risk Reviewer
reports, independent five-test/Ruff success, and protocol E2E pass (**2/2
each**, infrastructure 0). Primary full-reviewed both one-line diffs and
recorded **2/2 accept**. Each Reviewer needed one recoverable protocol
correction; first-report validity was therefore not 2/2.

This wider evidence supported proceeding to a single frozen expanded batch;
the resulting 11-case, one-round unified measurement is recorded separately
in `V1.2-EXPANDED-UNIT-BASELINE.md`. It does not prove universal reliability
or authorize v2.1 Coordinator release. Keep Primary acceptance, Reviewer
finding quality, and infrastructure failures separate from protocol E2E, and
qualify any replacement role model with `role_compat.py` before semantic A/B
testing.
