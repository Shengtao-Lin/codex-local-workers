## 1. 目标、完成定义与非目标

目标：Primary 委派一项有完整目标的工作，Strata 在批准范围内自主调查、选择步骤、
实现或整理、自测与有界修复；Primary 能读取完整成果，必要时给有依据的反馈，最终独立验收和生成回答。

“足够智能”的可观察定义：

- Primary 给目标、必要背景、范围和行为约束，不给逐步工具序列或完整修法。
- Strata 自行决定读取、搜索、实现、补充测试及恢复次序；不为每次普通动作请示。
- 宿主处理权限、版本、真实检查、预算和归档；模型不用重新确认这些机械事实。
- 对无法证实的事实明确说明缺口；缺信息与实现错误、权限拒绝分别记录。
- 允许内部重试，也允许一次预登记的 Primary 反馈续作；不能靠无限重跑获得通过。
- 最终成果可靠，且 Primary 不需要重新完成大部分探索与实现才能使用成果。

本阶段结束时交付一份“可用能力清单＋未合格能力清单＋证据”，不是通用智能认证。
研究、实现、续作分别授予有限资格，不把六格总分包装成普遍稳定性。

本轮不更换模型，不启用 LM Studio，不增加常驻 Planner/Coordinator/咨询者；不实施
任意 shell、模型生成脚本执行、公开网页到可写执行、无限递归、动态权限自授权。
现有独立 Reviewer 继续用于实现链；只读调查不强制经过 E→C→R 流水线。
不得借本计划清理旧历史、重构整个 runtime、修改生产默认或发布远端。

## 3. 目标架构与职责

```text
Primary：目标 / 背景 / 范围 / 完成标准 / 总预算
  → Strata：自主探索 → 执行或整理 → 自检与修复
  → 宿主：真实证据与完整产物归档；实现任务检查后fresh Reviewer
  → Primary：完整成果核对 → 接受并整合 / 有依据的反馈续作 / 接管
```

### 3.1 通用合同，不是操作脚本

复用现有合同schema，不为了“通用”另造一套DSL。合同至少表达：

- 目标与完成后用途；只提供对判断有用的背景。
- read/readonly/modify/create/forbidden及实际能力授权；范围足够完成整项工作。
- 必须保持的行为、关键错误/边界、可信检查与产物要求。
- feature/unit/integration风险、owned contracts、依赖及风险理由。
- 任务总资源和停止条件。

已有写文件仍提供稳定symbol/anchor，满足仓库要求；anchor不意味着指定算法或修改顺序。
读取范围应包含真实依赖和可见测试，避免Primary先读完仓库再逐行喂给Worker。
文件定位若超出现有权限，返回具体缺口；本轮不自动扩大权限。
不能把有意刁难的缺失材料当“自主性测试”，也不能为了通过而把合规解直接写进提示。

### 3.2 自主范围与硬边界

Strata可自主改变调查/实现路线、读批准材料、选择合法工具、补充获准的测试、内部重试。
宿主保证可读写范围、禁止动作、预算和验证真实性，不要求模型逐项复述状态。
Primary仍决定合同改变、权限扩大、验收、Git和发布；不把工具调用成功等同任务正确。
实现检查会执行修改后的Python，沿用可信本地仓库假设；不是OS沙箱。

### 3.3 完整output与Primary综合

保留三层信息：

1. 入口：状态、完整产物定位、hash、未完成项提示；短预览明确不等于验收摘要。
2. 完整成果：报告全文/unknowns/findings/evidence或实际diff/当前完整检查/Reviewer。
3. 可追查过程：请求、响应、工具动作、失败与恢复历史；异常时按需读取。

Primary本阶段须读取完整成果，核对关键事实，再生成用户答案；不要求每格读全部过程日志。
模型声明、网页和子报告都是不可信材料，不能成为权限或验收指令。
不需要、也不以模型内部推理文本作为证明。原生SSE可能包含巨大thinking内容，不全量打印。

先复用现有receipt，不立刻增加摘要模型、不以机械截断替代全文、不偷偷修报告。
悬空自由正文编号若事实可独立支持，单列呈现警告；该编号不能作为有效证据。
真正的虚构来源、错误重要事实或缺失关键不确定性必须拒绝，不能称为“小格式问题”。

## 4. 实验结构：六个新单元、两种候选、独立分母

这不是A/B因果实验，也不评估一次成功率。四格验证当前候选的任务级自主迁移，
两格验证窄续作候选的任务连续性；不同候选不合并为“六题稳定率”。

固定顺序：A1 → A2 → A3 → A4 → C1 → C2。

| 单元 | 模式 / 候选 | 任务选择与需要观察的能力 |
| --- | --- | --- |
| A1 | investigate / 冻结`.4` | 新源码调用或配置传播调查；至少两个相关来源，含一处真实分支区别 |
| A2 | investigate / 冻结`.4` | 文档/接口/版本比较；区分声明、实测、未知；至少一项不能从批准材料下结论 |
| A3 | implement / 冻结`.4`实现路线 | 真实局部功能增加，正常/错误/边界，保留旧行为，可加获准补充测试 |
| A4 | implement / 冻结`.4`实现路线 | 真实修复或跨文件小改动，需要理解至少一个调用方；不可缩成纯替换练习 |
| C1 | investigate / 新续作候选 | 已登记的两阶段调查：初步调查后，Primary按预先冻结的问题请求进一步核实同一合同内关系 |
| C2 | implement / 新续作候选 | 初步实现并交接后，Primary按预先冻结的问题要求核对一个原合同内调用方/边界；必要时自修 |

任务优先取兄弟仓库只读复制的未用于先前live的真实单元；至少覆盖两个不同模块/材料簇。
若全部来自熟悉仓库，明确为“熟悉仓库中的新任务”，不能宣称陌生仓库泛化。
精确选题在执行准备阶段决定，先检索近期任务索引与来源，禁止全量扫描所有历史归档。
旧MLflow/messages_output/metadata/ToolRegistry前缀题不充当新holdout。

### 4.1 任务冻结与隔离

- 每格独立只读上游快照、工作副本、合同、可见检查、私有终验；记录来源版本与hash。
- Primary先确认批准范围内存在合规解、依赖已具备、配置和检查真实可运行。
- 隐藏验收不得成为Worker修复提示；参考实现不得进入read/search/provider请求。
- 若用参考实现验证夹具，在单独参考副本执行，不污染Worker起点；开发准备成本单列。
- 不新增依赖或外部执行环境迁就题目；不把真实数据库/付费API作为这批必要条件。
- 候选先冻结，随后封存任务；registration写入后不换题、不改标准、不逐格改候选。
- A四格用同一manifest。C两格用另一manifest；新版本号先查重，不预设`.5`一定可用。

### 4.2 C1/C2不靠模型先犯错才有测试机会

登记初始合同中的完整总目标，说明任务含一次同范围跟进；第一阶段交接不是整项最终接受。
跟进问题预先写入Primary侧封存文件并hash绑定，不能根据成功答案临时给Worker提示。
跟进仅要求核实/补充证据，不追加原合同没有的边界、不扩大读写范围。

若首轮已完整正确，仍按登记问题请求核对；允许以新证据确认无需改动，记
“成功续作，未发生缺陷修复”，不能强迫制造代码修改或虚构缺陷。
若首轮无法形成可续作成果，保留首轮失败，后段记NOT_ELIGIBLE；不能计两次模型失败。
若发现真实合同内缺陷，可将事实和失败证据交回一次，沿用已有confirmed-defect路径；
登记为Primary反馈修复，不能混入完全自主首轮完成率。
如果必须透露隐藏验收细节或算法答案才能继续，该格标assisted diagnostic，退出自主资格分子。

### 5.1 C阶段资源保留，不充值

为了让“支持续作”有实际资源可用，C候选增加只对预登记两阶段任务的宿主分段限制：

- 首阶段超过分段上限而未交付，记明确的阶段预算失败，不暗中启动第二阶段救场。

这属于C的新实验配置，不改变A或任何历史预算。若代码无法用窄适配表示分段预算，

5. 普通失败继续剩余格收集迁移证据；安全、版本绑定、环境问题暂停受影响派发。

结果：研究资格需A1/A2两格独立接受，实现资格需A3/A4两格完整链接受。
只读正确的“材料不足”必须满足该任务预登记目标；不能把未完成实现改记为合理阻塞成功。
一条路线HOLD不清空另一条路线已有资格；但本批每个失败继续在原分母中。

### 阶段2：实现窄续作候选，先零模型负控

优先复用底层ledger、锁、编辑器、检查器、引用绑定、canonical存储和审查快照。
不得fork整套runtime，修改限于统一入口/反馈路由/恢复证据/分段预算与相应安装控制。
候选默认关闭，原首次执行路径保持兼容；为新行为选一个明确experimental开关。

建议接口为统一入口 `resume --task-id ... --attempt-id ... --feedback ...`；
这是待实现接口，当前不存在，执行模型必须先查看真实CLI再编写调用。

反馈必须区分：

- `verify_or_extend_evidence`：同合同内的补充核实；绑定先前完整产物与源码版本，不声称有缺陷。
- `confirmed_defect`：Primary已核实的原合同内缺陷；实现优先复用general_return的check/source绑定。
- 新需求、写范围或验收改变：拒绝混入resume，转明确的合同修订决策，本批不自动完成此扩展。

最小反馈载荷需有：原task/attempt/产物hash、owned contract IDs、具体问题或事实、
反馈分类、是否含语义/算法帮助；精确字段由实现适配现有schema，禁止不必要的庞大DSL。
不同模式按实际产物绑定：只读没有check，不伪造check_sha256绕过实现的缺陷schema。

恢复要求：

- 同task新attempt，所有预算累计，保存第一次结果与新反馈，禁止覆盖已接受/失败记录。
- 验证无active/pending、锁/源码/合同/配置当前一致；非法或重复反馈不触发provider请求。
- 已用资源与取消语义不因重启丢失；已取消任务不得自动复活，需明确Primary恢复意图且旧事件保留。
- 只读恢复得到原报告、当前可用观察索引、unknowns与新问题；实现得到当前diff/检查/失败和任务合同。
- 不必重放全量日志，也不能把失效源码观察当当前事实；预算足够时可重新读取批准材料。
- 模型笔记若引入，只作不可信的导航；本轮优先不新增notes工具或摘要模型。
- current status指向最新attempt，所有旧result可寻址，不能按错误文件名字典序选错结果。
- 实现更改后的检查及Reviewer交接仍自动进行；未变代码不能制造新的审查抽样机会。
- 保持取消传播、串行写锁和单模型驻留；scope控制不能被resume变成任意路径读取。

若A暴露了独立语义失败，不顺便在续作候选中堆提示修它。A故障影响续作安全/真实性时，
先按第9节作窄修订或停止对应路线；不能用C候选成功改写A失败。

### 阶段3：续作离线控制与C1/C2 live

离线必须覆盖以下行为，不要求凑固定测试数量：

1. 当前版本合法resume成功；task/attempt/产物错配、路径越权、旧source/check拒绝。
2. active/pending/锁冲突/重复反馈/取消状态不静默执行；不会产生真实provider调用。
3. 重启前后资源一致；分段限制与总限制同时有效，attempt不充值。
4. 只读follow-up不被强制伪装成缺陷；无写权限和无任意shell不变。
5. 实现confirmed-defect原机制继续成立；新增问题不能改变原合同和保护输入。
6. 每次有效编辑使旧检查失效；零/全跳过测试与过期检查不能交接。
7. 同一审查输入不重抽；实质修改才触发新fresh Reviewer，旧审查结果保留。
8. 完整output/unknowns/来源不丢，preview不冒充全文，恢复不清除原失败。
9. 上下文恢复包含当前合同、现有成果、关键失败、反馈和剩余额度；恶意笔记不能改权限。
10. 新版本安装清单含新增模块；首次执行兼容控制和CLI prepare/status/cancel仍正常。

复用同版本控制；对真实改动边界增加负控，不写镜像实现的无意义测试。
离线缺陷可自主修复，保留每次失败；控制未通过不启动C的live。
控制通过后冻结新候选，再封存C1/C2任务、分段/总预算及跟进问题，写独立registration。
执行C1再C2；普通失败保留并继续安全的下一格，不临场更改反馈或候选。

live必须记录“有续作入口”与“模型实质利用了续作证据”的区别。
仅离线状态传输成功不能宣称live恢复有效；没有真实缺陷则修复转化能力记NOT_TESTED。

### 阶段4：独立验收与可用版收敛

Primary读取完整产物，不用Worker自评分替代验收。研究核对关键事实、来源及不确定项；
实现核对当前diff、完整项目检查、保护终验、Reviewer判断与重要语义边界。
同一事实若canonical引用正确但模型解释错误，仍是语义错误。

在隔离干净副本验证已合格路径安装、配置示例、prepare/run/status/cancel和新增resume。
保留两个实际配置profile，不能宣传一份config把所有功能打开。
生成“监督试用候选”交接与适用范围；不自动push、升级真实项目或修改生产默认。
只有资格表中通过的能力才能写入用户可用说明。若某route不合格，保留入口实验状态。

## 7. 验收指标和资格表

逐格分别记录：

- registration/executed/not_run/not_eligible；任务曝光情况与源版本。
- 合法交付、所需工作正确、当前检查、Reviewer结论、Primary最终接受。
- 内部修复、协议恢复、no-op、有效证据新增、有效编辑；无改动续作不自动等于no-progress。
- 错误被检查拦住 / Reviewer错误放行 / Primary拒绝 / 已知最终错误接受。
- 误拒、证据不足、范围阻塞、资源耗尽、基础设施失败、Primary接管。
- 模型请求/输出/上下文、加载/执行/检查/review/等待时间；unknown不能填0。

资格分别判断：

| 能力 | 本阶段有限门槛 |
| --- | --- |
| 新题只读任务 | A1+A2都完成独立事实验收，无重大虚假来源或越权 |
| 新题实现任务 | A3+A4都通过当前可信检查、fresh review和独立终验，无人工代写 |
| 只读续作 | C1初步成果及后续核实均可追溯，使用原任务剩余额度，完整结果独立接受 |
| 实现续作 | C2阶段成果和核实/修改当前有效；有修改时检查＋fresh review＋终验成立 |
| 无指导自主性 | 对应格只有初始目标/约束与最终验收；没有过程语义修法或人工定位救援 |
| 反馈协作能力 | 对应格接受了明确登记的Primary反馈；与无指导自主成绩分列 |

总release-ready为上述四项任务能力都具备有限通过，安装与负控通过，边界说明完整。
这不是高置信稳定率；每类样本极小，不外推任意任务，不声称经济收益已证明。
已知重大错误经Reviewer放行，即使Primary拦住，也需单列审查HOLD；不能以实现完成率掩盖。
从历史没有观测到错误放行不能推断本批检测率；复用既有相关负控，未覆盖则明确缺口。
若需要补全新的审查方法/大批负控，作为关键阶段结论，不在此偷偷扩成第二个项目。

## 8. Primary工作量与成果使用实验

使用现有工具/事件记录，不新建成本平台。分开记录：

- 一次性：harness实现、实验夹具、封存私有验收、安装控制。
- 每任务：合同准备、已有测试选择、额外保护测试、定位、反馈、协调、最终审查和答案整合。

建议每格 `primary-involvement.json` 字段：
`provided_algorithm`、`added_semantics_after_start`、`located_missing_dependency`、
`edited_worker_code`、`rewrote_report`、`confirmed_defect_feedback`、`planned_followup`、
`final_review_only_after_dispatch`；记录具体动作及时间来源。

初始合同和测试准备本身也有成本，不能因没有代写代码就称“Primary零工作”。
补充信息、指出失败事实、给出算法与直接代写不同，不能全记成同一类assisted或全忽略。
提供新语义要求/具体修法/隐藏答案者必须标assisted，另列，不能计无指导完成。

Primary每格产出一段可直接回答用户的最终结论，说明用了哪些Worker成果、哪些经核对
修正或排除；不要求重写Worker完整报告。若必须重新调查绝大多数问题，记录“协调收益不足”。
主动时间可人工计时则说明方法；工具等待墙钟不是主动时间。无完整统计写unknown。
不做Primary-only配对就不承诺节省百分比；weekly仅停止线观测。

## 9. 失败分类、修订上限与分支

每格结束写简短 `analysis.json`：观察、最早可确认偏离点、证据路径、根因等级
confirmed/supported/hypothesis/unknown、下一步、候选是否允许改。不要仅按最后报错归因。

| 类别 | 证据与动作 |
| --- | --- |
| 环境/夹具 | 启动前错误不计Worker失败；修复后重新冻结准备，原事件保留；已有模型输出则保留曝光 |
| 确定性harness故障 | stale状态/恢复丢失/检查漏机会等有实际证据；允许窄修订＋负控＋固定复验 |
| 交付机械负担 | 区分合法完整报告与实质工作；非关键警告记录；真正交付失败保留，不偷偷裁正文 |
| 合规行动被挡 | 记录实际请求、拒绝原因及完成任务必要性；先确定是否合同失配，不立即扩大权限 |
| 语义失败 | 事实足够仍错，先归档最早偏离；可一次事实反馈，不重复给旧题提示直到过 |
| 缺信息/权限 | 具体列出缺口；不自动计能力失败，也不计完成；新信任范围需用户决策 |
| 审查漏错 | 与Coder错误分开；冻结受影响资格，不能通过删Reviewer或降低标准解决 |
| 高Primary成本 | 正确率可以通过但经济性unknown/不足；先记录，不伪造节省结论 |

### 9.1 固定修订额度

初始A四格与C两格之外，整个计划最多一个live后窄修订候选，最多4个额外单元：
两个相关已暴露回归＋两个同族新迁移。若缺两个相关回归，用已有负控离线覆盖，
不制造重复题凑数；不得增加超过两个新迁移单元。新批独立registration、分母、decision。

修订只能修一个有证据支持的机制，不同时换预算、提示、采样、模型或验收。
若问题确为预算/分段调度，唯一修订可以专门改变它，但须公开登记具体上限和影响，
保持权限与正确性门槛；不能把新成绩解释成原预算成绩。没有证据就不消耗live刷分。
修订后的已曝光回归只证明修复，不恢复holdout身份。新迁移通过才支持新候选有限资格。
未触及的route若manifest模块影响分析和兼容控制支持可复用旧证据；不合并不同版本总分。

两项不同任务出现相同机制失败、一次重大信任故障，或窄修订仍不能达到相应门槛时：
停止该方向，写明确能力/设计边界和可用子集，不继续开第二轮窄修订。
无关安全的route可完成固定注册内容；不得用新简单题冲掉原失败。

### 9.2 何时自动更新计划，何时需要用户

可自主决定并记录：确切选题、文件命名、复用实现、夹具修复、既定负控、代码bug修复、
固定批次普通失败后的继续、一次有证据窄修订、按已有边界收敛资格。
这些写附加amendment并标生效批次，不回写已关闭registration。

需要停下交接：更换模型、扩大执行信任面/任意shell或网络写入、修改兄弟仓库/Strata安装、
修改生产默认、发布、取消独立审查、放宽正确性标准、大规模重构、超出修订额度。
达到明确阶段决策不是失败；交接应说明已经可用什么、缺什么、需要何种下一项决策。

## 11. 最终交接格式与停止条件

停止条件：达到本阶段受监督release-ready；达到固定修订停止结论；需要重大决策；
实际weekly used达到50%（用户更新优先）；或环境无法安全继续。

handoff必须包含：

1. 当前候选、manifest、工作区、实际usage/模型驻留、active批次/进程。
2. A与C及修订各自注册/执行/未运行数量、失败与assisted，不能合并掩盖。
3. 调查、实现、续作、审查、成本各自结论；实验通过/受监督资格/生产启用区分。
4. 至少一条失败或恢复轨迹；若无缺陷修复，明确尚未实测而非补造成功故事。
5. 实际Primary介入、完整output如何被使用、是否重复调查；不可测项unknown。
6. 变更文件/验证/剩余风险、已保留的现有改动、无commit/push/默认改变的核对。
7. 下一步只给一个由证据支持的动作或待决策问题；不自动扩成联网/脚本/递归大路线。

## 12. 外部参考及使用方式

上轮已读取的一手资料，用于架构启发，执行时无需重新大规模研究：

- [OpenAI tools / agents-as-tools](https://developers.openai.com/api/docs/guides/tools)：
  主代理保留面向用户的回答职责，子代理作为工具承接工作。
- [Deep Agents subagents](https://docs.langchain.com/oss/python/deepagents/subagents)：
  隔离中间过程、返回成果；不意味着Primary必须丢掉访问完整证据的能力。

这些是设计参考，不是iq3_s的性能证明。本计划保留单模型、完整证据和可信宿主，
用新任务与反馈续作测试“自主执行是否有用”，不以工具数量或角色数量衡量智能。
