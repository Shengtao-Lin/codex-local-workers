# v2.1 localization-only implementation slice

Status: restricted one-unit handoff implemented; autonomous/general Coordinator routing is **not enabled**.

Primary-owned feature `v2-1-localization-route` has **high feature and integration risk** because state recovery, authorization boundaries, and worker handoff must remain consistent across process failure. Splitting the work does not reduce those invariants.

| Unit | Risk | Dependency | Owned contract | Reason |
| --- | --- | --- | --- | --- |
| Durable state | high | none | `state-sequence-authority` | Atomic process-boundary state and stale-plan rejection are lifecycle invariants. |
| Capability gate | high | durable state | `localization-only-authority` | Unsupported semantic questions must be rejected before worker dispatch. |
| Diff/scope guard | high | capability gate | `changed-path-authority` | Imported modules, manifests, and all changed paths require independently observed authorization. |
| Duplicate-raise quality | medium | none | `no-new-dead-raise` | Deterministic source-quality regression; no authority expansion. |
| Live routing and recovery | high | first three units | `single-unit-handoff` | Must reuse Coder→Reviewer handoff without treating worker output as Primary acceptance. |

Current implementation:

- Durable state is stored in the repository `.agent` tree through an exclusive writer lock, a same-directory temporary file, `fsync`, atomic replacement, and expected-sequence comparison. Malformed, stale-plan, and locked state fail closed; a pre-existing lock is never silently removed.
- A proposed dispatch requires explicit `localization_only`, a schema-v2 packet bound to Primary's plan, a successful full `locate` Explorer report, current source hashes and quotes, no unresolved localization uncertainty, and an authorized writable implementation target. The report has `semantic_verdict: not_evaluated`; it cannot certify behavior.
- Coder's existing pre-validation diff-quality gate now rejects newly introduced adjacent identical `raise` statements. Pre-existing duplicates are not reclassified as new defects.
- The restricted `.local-agents/coordinator-localization.py` entry point accepts a Primary-supplied packet and a completed **full** Explorer locate report, advances the durable state once, then calls the existing `local-unit` Coder→Reviewer handoff. A second dispatch for the same running unit is rejected. It never records Primary acceptance or feature readiness.
- Before state advancement it writes one immutable dispatch record keyed by run id. The record binds the Primary plan fingerprint, packet/report hashes, and bounded Explorer path/line/hash references without raw source quotes. A reused run id is rejected even if state is lost; interrupted workers remain `running` for Primary inspection, never automatic replay. `coordinator-localization.py --inspect-only` reconciles that record, durable state, Coder handoff, and Reviewer archive without changing any of them.
- `coordinator-localization.py --plan ... --inspect-feature --unit-id ... --run-refs ...` checks all archived unit acceptances and the current integration evidence without writing Coordinator state. A successful result means only `eligible_for_primary_final_review`; Primary still reviews the cumulative diff and makes an explicit feature decision. Missing, forged, or stale evidence fails closed.
- A completed Coder run whose canonical `completed.json` says `failed` may enter `rework` only through `--recover-terminal --authorization ...` with a Primary-authored file at `.agent/primary-reviews/<feature_id>/recovery/<failed_run_id>.json`. Its schema separately binds the originally dispatched packet bytes and the runtime's canonical archived packet bytes, plus the plan/completed hashes, expected state sequence, new run id, reason code, and rationale. The next dispatch requires that same authorization, fresh Explorer evidence, a fresh run id, and a packet that does not expand the previous read/write scope or weaken read-only/forbidden protection. Incomplete archives, interrupted/blocked runs, or uncertain process state still require Primary takeover rather than this transition.
- The trusted handoff checks cumulative-diff paths against runtime-attributed authorized edits. A manifest or other extra path in that diff blocks Reviewer dispatch even if a report omits it.
- The same handoff compares newly added Python static imports with immutable source preimages. If an imported local module exists outside the packet's read/write scope (or under a forbidden root), Reviewer dispatch is blocked; authorized local imports remain allowed. This is not a proof about dynamic imports or all runtime dependencies.

The restricted entry point does **not** launch Explorer, autonomously choose rework, or resume an archive-incomplete running unit. Primary must invoke `local-explore` in locate mode first and decide recovery after read-only inspection. A separate `materialize_bounded_packet` function can derive a schema-v2 packet from a Primary-authored plan and a narrow unit proposal; the route itself does not let a model author or revise Primary's contract. Simulated process-loss, double-dispatch, terminal-failure rework, multi-file evidence, out-of-scope target, manifest-diff, and static-import fixtures pass. Remaining before autonomous routing: safe treatment of archive-incomplete process loss, broader integration review, and repeatable multi-case model performance. This slice does not authorize feature acceptance.
