# 调查报告的窄接口修订：准备稿

2026-10-25。承接practical-readiness已观察到的多次证据索引错配。
当前task.9固定12格继续原样完成；本稿及离线准备不改变任何已登记输入或成绩。
是否启动新live，先根据完整task.9 decision记录判断，由用户已授权的自主执行处理。

## 单一改动

普通调查使用可选compact-v1报告：status、summary、evidence、unknowns。
模型在summary描述答案及实际问题，并给代表性path/line引用；不必把相同事实
再复制成带contract_id/severity/evidence_index的findings数组。
宿主显式将四字段wire转换为既有canonical五字段（findings=[]），保留原始wire，
不删除任何模型已提交的finding、不重写措辞、不推导语义或修复错误引用。
旧wire在新profile中拒绝，反馈明确四字段；新wire在旧profile中仍拒绝。
Reviewer五字段、缺陷报告、实现/检查、权限、预算、技能内容均不变。
此改动减少重复事实和交叉索引，不保证消除错误推理。

## 离线控制

真实统一/native控制加载新schema并交付；完整summary和unknowns逐字保留；
原始wire归档可见，canonical显式标明转换；旧候选默认不变；未观察/越界/漂移
引用仍拒绝；无证据不能伪装answered；非法字段/数组/状态仍消耗原协议预算；
同预算收尾和一次机械纠错不变；Reviewer及能力工具组合不自动启用。

## 新批次原则

若task.9继续呈现多次索引错配，可激活一次本修订，冻结task.10。
不重算task.9；旧题只做已暴露诊断。新迁移至少三种问题各两次，六格固定顺序，
普通失败完成剩余单元、输入漂移/安全/驻留/weekly>=50停止。
优先选择预算内可调查且含真实依赖/控制流区别的问题；不把高风险DB结论变简单
来冲旧失败。至少一项明确验证“缺失证据应限制结论”，不要求Worker猜隐藏答案。
本批同时检验真实的监督协作：保留task-v1现有首阶段4普通请求、共享8普通请求
及每阶段最多一次机械纠错、总10，16工具/12证据/900秒。初次答案正确便终验，
不为用完额度强制续作。首交付合法但存在原合同内可核对的错误时，Primary至多
给一次具体的原稿争议和原批准来源位置，由Worker自主核对、修改答案；不补要求、
不提供正确算法/参考答案、不扩大来源/权限。续作绑定原结果、原源码和原总账。
初次无法合法交付按原机制停止，不新建任务充值。

六格均在此有界流程内正确完整、无实质过度推断或虚构执行才能通过本范围
受监督调查门槛。分别统计首次自主接受、Primary指出证据争议后的恢复、assisted
和最终失败；不将监督恢复写成一次自主成功。Primary若提供新语义要求、额外事实、
算法或代写，标assisted且不计本门槛。记录每次反馈内容和成本，不能靠重抽审查。
这是新实验的恢复口径；task.9原来的无语义反馈6/6标准和失败保持原样。
本修订后若同类语义错误继续出现，记录能力/任务包边界；不继续堆提示修旧题。
实现和benchmark批次仍可独立推进，综合试用资格保持分层。
