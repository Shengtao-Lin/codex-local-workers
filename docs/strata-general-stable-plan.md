## 1. 要交付什么

第一目标是 **Strata Worker 0.2.0 的通用编程稳定核心**：在可信本地 Python 项目
中，Primary 给出一个行为完整的任务、权限与验收标准，Strata 自行定位、修改
相关源码、补充测试、自测和有限修复，最后返回可核查的变更供 Primary 验收。
同一安装可以连续处理不同任务；失败能保留证据并安全退回，无须清空历史重来。

“通用”首先指摆脱特定题目、函数观察器和单函数形状的绑定，不承诺所有语言、
任意规模、所有模型或不可信仓库。首批可交付范围：

- 一个任务最多 4 个源码文件、2 个补充测试文件；总计最多 6 个创建/修改路径。
- 可修改多个函数/类及任务明确批准的内部接口；可读相关调用方和测试。
- 可以新增批准路径的 Python 源码/测试；不新增依赖、不执行迁移、不直接提交 Git。
- 支持明确的局部功能、行为兼容修复、跨文件内部改动、测试补充。
- 安全、认证、破坏性数据操作、事务/并发及公共兼容边界继续由 Primary 按高风险
  审查；没有相应资格证据时走 Primary，不用拆小文件降低风险。

后续扩展是同一个子代理的只读审查、按需 Skills 和受控文档网络能力。它们分别
标记资格，不阻止核心版本先交付，也不随核心通过而自动开启。Coordinator 和
递归子代理不属于 0.2.0 核心；不重新搭一套串行 E/C/R 模型切换流水线。

## 3. 设计决策

### 3.1 唯一职责链

```text
Primary：意图、风险、行为合同、权限、验收
  → Strata 单会话：调查 → 成批修改 → 看真实检查 → 有界修复/补测试
  ↔ kit host：范围/版本/任务账本/编辑/检查/证据/取消
  → ready_for_primary：当前变更与完整证据
  → 可选 fresh 只读 Strata review（另一个上下文，同一驻留模型、串行）
  → Primary：accept / 有证据的 rework / replan / takeover
```

Strata 决定批准任务内的实现步骤。Primary 不必逐个 read/edit 指挥，但权限不足、
行为合同冲突、风险变化仍回 Primary。模型不决定自己的权限、预算或验收规则。
自审和同模型 fresh review 都不等于独立正确性证明；核心版继续要求 Primary
检查实际 diff 和独立测试，不沿用旧 E/C/R 的“小风险可省全文审查”资格。

### 3.2 产品协议：一个任务，一个累计账本

任务包分为稳定的任务合同、宿主执行配置、运行结果三部分。对用户只暴露一个
简短任务文件；准备器机械生成底层 packet/source-policy/check manifest，避免
Primary 同步维护多份重复 JSON。已知 anchor 可复用或机械提取，不要求预写算法。

必须绑定 task/unit/attempt、合同版本、源起点、读写清单、保护测试/配置、运行时
与验证 profile。`task_id` 是同一工作单元的预算身份；换 run_id 不补额度。
scope/合同变化要新的批准修订，继承已耗预算和历史；不能包装成新任务绕过停止。

拟议产品命令：doctor / prepare / run / status / cancel / resume / export。
这是接口草案，不是现有可执行命令。prepare 预览再落盘；status 不触发模型；
resume 仅续同任务剩余额度；export 导出带 preimage/hash 的 patch 与证据，不操作
Git、不自动写回真实仓库。exit 0 只代表命令完成，必须读取机器状态。

按任务命名空间保存所有材料，如 `.agent/tasks/<task>/attempts/<attempt>/...`。
canonical 旧路径若保留，建立明确映射，禁止双写两份“权威结果”。最新状态指针
可更新，历史事件/检查/decision 不可覆盖；不迁移或删除已发布预览的旧历史。

### 3.3 工作区与连续任务

核心版首先支持一个长期存在的**隔离工作副本**中连续运行任务，安装不必重做。
同一项目只允许一个写者；每项新任务绑定前项最终状态与当前文件版本。
已有未提交改动进入只读基线，不自动 stash/reset；重叠变更必须检测。

验收通过的任务可成为下项任务起点。失败的部分修改保留，后继依赖任务不自动
运行；Primary 选择修复、保留为明确新起点或导出后丢弃整个专用副本。取消只终止
本任务拥有的子进程，不能杀驻留模型、其他项目或用户进程。

首次交付仍不自动直接编辑真实主工作区。工作副本是变更隔离，**不是 OS 沙箱**；
测试/conftest/import 仍用宿主权限，适用可信仓库。直接主目录写入和不可信执行
另行准入，不能靠扩大工具 allowlist 获得。

### 3.4 多文件编辑：一个小协议，不恢复旧复杂动作语言

保留 read/search/block，增加一项批量变更提案；沿用 JSON 工具调用。现有文件
使用 current file hash + 精确唯一匹配的块替换，新文件使用批准路径 + create。
不并列开放多种 patch 方言，不 fuzzy apply，不按猜测行号替换，也不要求整模块
重写。单函数旧提案可经兼容层进入同一编辑底座。

一次提案内先解析、检查所有路径/hash/匹配/大小/格式化候选，再提交完整变更集。
有一项无效则零写入。落盘中断不能假装具备跨文件 OS 原子性：归档写前日志与
preimages，标记不完整事务，恢复时核对后修复或停在 conflicted；绝不接受半写。
补充测试与源码可同批变化；保护测试、检查配置、runtime、任务权限不可改。

每次**有效变更集**都自动触发完整批准检查；同批多个文件算一次有效编辑，记录
每文件变化。格式化后绑定新 hash，模型 no-op 不算有效编辑；格式化不能动保护文件。

增加一个 `kit_submit` 交接意图动作，不再同时引入完成标记字段：只请求宿主
核对当前全部证据并交接，不宣称 SUCCESS。
中途 checks 绿色可继续写补充测试；submit 若证据已是当前版本不重复执行同一检查。
缺测试、旧证据、失败或未完成必需文件时拒绝交接并返回事实；模型仍可用剩余额度
修复。不要求 VALIDATE/FINISH/重复成功确认，不允许模型选择少跑检查。

### 3.5 查找、上下文和恢复

prepare 从 Primary 批准的源码/测试根机械枚举 manifest；先排除密钥、运行历史、
隐藏验收、构建产物和 reparse 路径，再给模型紧凑目录索引。限额是显式配置；超过
上限必须报 scope_too_large，不能静默少读后声称文件不存在。首批仍125文件上限。
read/search 在 manifest 内按需取证，可提供分页；model 不需要 Primary 逐个找行号。

模型上下文分三部分：不变合同和权限摘要；宿主生成的当前状态；按需原始证据。
当前状态含当前文件 hash、实际改动、检查失败与已解决项、剩余额度、未解问题。
旧检查/旧引用明确失效；源码路径和状态来自宿主，不信模型自述“已经测试”。
无可靠失败映射时保留原始诊断，不造智能进展评分器。

优先复用现有 delta 投影并扩展多文件；接近已验证客户端上下文阈值时进行一次
确定性重建：合同 + 当前版本 + 当前失败 + 有来源的关键证据，原始历史留盘可读。
按真实 token 计数或保守可核查估计预检，不能把字符数假装 token。无可靠计数则
提前有界停止；不盲目扩大上下文。压缩控制需证明权限、失败、预算不会丢失。

同任务允许内部修复及 Primary 基于已确认缺陷的一次退回，统一消耗剩余额度。
退回内容给合同/实际错误/位置，不代写补丁。新增语义解释、具体算法或隐藏测试
细节一旦提供，记 assisted，不能计自主完成。断线后核实是否已发请求/落盘再恢复，
不重放未知完成状态的写操作；不以重启 native session 重置限额。

## 4. 新预算与成本口径

这是新 profile `strata-unit-v1` 的设计预算；不改旧 preview 上限，不把新成绩归因
为旧版同配置进步。实现前先 scripted 重放最坏路径，确认检查机会真实可达。

| 资源 | 实现任务的上限/规则 |
| --- | --- |
| 实际模型请求 | 16；所有 HTTP 尝试、协议恢复、重连重发均计入；同任务累计 |
| 工具动作 | 24，其中 read/search ≤16；submit/block 也计入；不再加含义混杂的 model+tool 共享18池 |
| 有效编辑 | 4个完整变更集；每集至多6个批准文件 |
| 完整检查 | 起点1次单列；每次有效编辑对应1次完整写后检查，共4次；检查全套批准 profile |
| 格式化 | 每个提案至多1次受控准备，共≤6次；单独记耗时；不得占掉有效编辑的写后检查机会 |
| 每次输出 | 12288 tokens，包含当前4096 thinking；累计保守上限196608，保持已测采样 |
| 单次取证 | read ≤120行、search ≤10结果；页码/范围可续读，同样计费 |
| 协议/传输恢复 | 合计最多2次，计模型/工具/时间；完整但被截断的工具调用也不能执行 |
| 无进展 | 同版本相同提案2次、连续3次无新证据停止；实际新证据/有效编辑分别记录 |
| 时限 | 活跃任务累计1800秒（含请求/检查/收尾）；单请求≤600秒，单检查命令≤180秒且受总截止约束；不够完整检查时停止，不能假通过 |
| 恢复与加载 | Primary等待时间单列，不能用无限等待延长活跃执行；加载就绪等待≤900秒、每10秒探测，不派推理，单列耗时，默认不主动reload |

4次编辑为首次实现与最多3次修复/补充留空间；16请求容纳调查/4提案/交接及少量
恢复；这些是可检验起始值，不能保证题目可解。保留最后编辑/检查的可用机会，
不要机械拒绝为修复必要的读取；余额明确反馈，额度不足即记录 budget_exhausted。
任何调整都进入新版本/新 registration，不在一批中边失败边涨上限。

调查/只读审查使用单独冻结预算（建议各8/10请求、12次取证、900秒、0编辑），
不可与实现任务混算完成率。加载在同驻留模型下摊销，但实际冷启动单列。
记录 Primary 的准备、定位、语义指导、协调、接管和终验；研发一次性成本单列。
unknown 如实保留；weekly used 只是停止线，没有 Primary-only 对照不声称省多少。

## 5. 实施阶段、产物与失败出口

每阶段先离线控制，必要边界通过才 live。简单实现选择可自主决定；新模型、
扩大权限、降低门槛、真实仓库破坏性变更或发现需改变产品信任模型时才回用户。
阶段完成写 decision/handoff 后可按下一阶段继续，不因普通失败无限停留或换题。

核心首次候选最多28个live单元：旧回归6 + 新任务12 + 修复4 + 新项目留出6；
前置门槛失败则不启动后续部分。按每格30分钟上限，最坏为14小时活跃本地执行，
这是上限而非预计耗时；加载、离线准备、Primary审查另列。长执行分批落盘，
跨会话接续同一registration，不能把已完成格重新计数。S5另有16个只读单元，
不属于核心的28格或本次开发必跑范围。

### S0：建立可维护开发基线（0 live）

1. 核对 Get-Location、Git dirty、实际 usage、现有进程与驻留；不打断正在执行批次。
2. 验证已发布 commit/ZIP/manifest，保存当前工作树状态摘要与所需文件 preimages。
3. 在独立工作区从已发布产品提交准备 `strata-dev` 开发分支，保持原脏工作树和
   main/strata-preview 不变。未获本阶段 commit/push 指令时仅本地开发，不发布。
4. 以产品 `runtime/.local-agents/` 为该分支唯一实现来源；有选择地导入本计划及
   必需测试，记录来源 hash。不得复制900多项无关未提交文件或全部实验档案。
5. 建立可独立运行的产品测试入口；原有安全模块继续复用。先搬移不改语义，
   后续逐步替换版本链命名；不把减少文件数量作为重写验收器的理由。

交付：source-map、冻结清单、最小开发/安装 smoke、风险合同表。
门槛：产品可从明确源码打包；旧入口行为和包内容可追溯。依赖无法分离则先登记
其必要性，允许保留惰性legacy模块，不能为了“Strata-only”破坏已验证路径。

实施单元按行为拆分而非按文件拆分；整体feature/integration risk为high。
至少记录以下不可降低的边界：任务身份与预算不可重置、编辑权限与版本绑定、
完整检查与交接、取消/恢复的一致性均为high；文档/只读汇总可small；上下文投影
最低medium，触及权限/预算继承的部分仍为high。每单元列owned contract IDs与
依赖。发布分支的代码布局与本文件列出的旧源码路径不同，source-map应给出
准确对应位置，后续只修改一个实现来源。

### S1：任务身份、材料命名空间、连续任务与恢复账本（0 live）

将固定policy/report路径移入任务/attempt空间，机械转换简短任务规格；增加
status/cancel/recovery检查。项目/模型配置与任务合同分开。先实现同隔离副本两项
顺序任务、同任务两attempt共享限额，不引入并发写入。

离线必须覆盖：旧ID重入拒绝；两任务不串证据；run变化不补额度；外部文件变动；
锁冲突/锁所有者退出；进程重启；取消后无新写入；不完整事务/未知请求状态。
未确认所有者与状态前不删锁。交付 ledger/state schema、故障恢复手册与控制记录。

### S2：通用编辑、完整检查、稳定上下文（0 live）

实现3.4的变更集和交接意图、3.5的manifest/增量投影，注册4节的新预算。
从单函数guard迁移到任务批准范围/版本guard；不修改旧profile的资格。
新 profile 读取冻结 check manifest：项目声明必须运行的测试/静态检查都执行。
不再固定假设所有项目恰有3个检查ID，但已用Ruff/Pyright的项目不能移除它们。
缺少关键验收工具/有效测试时 blocked；Worker补充测试不能代替保护验收。

先从Consolidated中分出可复用的受控编辑/检查/归档接口，再让新任务profile组合
这些接口；旧单函数入口保留适配。不得复制整份WorkerRuntime到新runner再各修
一遍。若提取影响面过大，先做窄接口接缝并保持旧回归，剩余解耦不阻塞功能验证。

新增负控围绕：越权/路径别名/reparse；旧hash；非唯一替换；变更集半失败；
新文件冲突；保护测试/配置漂移；检查0执行/全skip/漏命令；旧绿色证据；格式化
越界；终态后动作；超时/截断；压缩丢失合同；resume重放。复用同版本有效控制，
不为仪式重复跑无关数百项。真实脚本轨迹包括失败→修复→全检查和中途绿色→
补测试→最终交接，证明控制流正确；这些仍不是模型能力成绩。

交付：冻结工具schema、产品候选hash、offline decision。任一安全/证据控制不
通过则禁止 live；可针对确定性缺陷修复后新批记录，不降低该控制。

### S3：实现与恢复能力（先冻结，再模型测试）

新候选先跑旧三类任务各2次，6格为兼容回归，全部接受；与历史不合并。
随后准备6个未用于该候选调参的真实任务，每题2次，共12格。来自至少两个可信
项目副本；兄弟仓库只读复制，在kit内运行。无需新Docker/依赖来迁就题目。

| 分组 | 两种任务示例；最终选题需校验真实源码和可行解 |
| --- | --- |
| 局部功能/测试 | 可选参数规范化并补错误路径测试；已有结果摘要增加明确边界与补充测试 |
| 保持行为的修复 | 稳定排序保留重复键顺序；缓存key或事件聚合保留既有异常/顺序语义 |
| 依赖/跨文件 | parser→consumer同一内部值的端到端兼容；内部API变更同步两个调用方与测试 |

上述是题型，不是已冻结题目；不能原样复用旧messages_output/metadata/hash后
称未见迁移。Primary只给行为结果/真实边界/批准根/保护验收，不给修法；先证明
批准范围内存在解。参考实现与隐藏验收留在模型不可读路径。

冻结前先验证原项目环境与既有回归可运行；新增需求测试在旧源码上按预期失败
是合法任务起点，不应被当成基础设施故障。逐项登记expected baseline failures，
起点绿色也不能触发任务完成。非预期导入/依赖/检查器故障先修实验，不能交给
模型猜环境。隐藏验收只在独立终验执行，其失败细节不流回自主格的修复上下文。

两次运行同起点、独立副本，预登记题目顺序交错而非失败后择题。普通失败继续
固定矩阵；安全/基础设施/驻留变化/预算停止新派工。每格含全部内部retry；严禁
“再跑一格成功”覆盖原失败。Primary语义帮助单列 assisted。

另冻结4个有真实测试报错的错误起点：静态错误、异步遗漏、跨文件不一致、行为
回归各一。让Worker只据原合同/源码/实际诊断修复；不发解法。这是**给定错误
起点的修复能力**，与模型自行犯错后的自恢复分别统计；自然发生的自恢复照实
报告，不强迫每格故意先写错。新补充测试需经独立缺陷注入证明能检出相关问题。

门槛（本计划建议，须在该批启动前固定）：

- 新12格最终独立接受≥10/12，且三组分别≥3/4；自主成绩不含assisted/接管。
- 4个修复起点≥3/4接受；其余均正确失败/阻塞，无循环逃逸或假交接。
- 0越权写入、0漏掉必需检查仍交接、0接受时证据过期；发现直接阻断该候选。
- 持续存在已确认合同缺陷的“ready”单列语义漏检，Primary必须拒绝；当前候选
  不能带着已知未解决漏检进入发布，补可信检查/代码后另冻结并回归。

这些是工程发布指标，不是总体成功率的统计保证。12格不足以宣称“所有题型稳定”。
最终接受要求每个被接受单元完整满足合同，10/12绝不授权接受另2个错误结果。

### S4：新项目留出验证与实际使用流程

S3合格后冻结候选，不改提示/预算；再取3个新任务（覆盖三组）各2次，共6格。
任务由未用于该候选调参的材料产生，不向Worker泄漏参考/隐藏测试；看过结果
后该题永久转已暴露。至少包含一次同安装的顺序任务，第二项起点必须绑定前项
已验收输出；依赖未满足记NOT_RUN，不能假装模型失败。

门槛：≥5/6自主完整接受，每组≥1/2；安全与证据要求仍为0违反；所有计划格
完成才决策。剩余失败必须能明确安全退回、没有已知系统性缺陷或语义漏放行。
本阶段只允许原任务包与现有真实检查反馈，不提供临场解法。

另外完成实际 ZIP 从新路径安装、相同安装多任务、取消/重启/旧版本拒绝、导出
patch冲突预检及文档复制流程；尽量复用矩阵执行，不另为每个包装功能重复live。
不承诺原地升级：第一稳定核心可仍采用并存版本目录+显式配置切换，保留旧包和
任务账本；安装器不能覆盖用户项目配置。新版本不可误读旧epoch成有效验收。

通过后可标 `CORE_STABLE_SCOPED`，发布支持范围与成功/失败表。仍需Primary终验。
未有成本对照时只陈述实际介入/时间，不能宣传“节省X% usage”。

### S5：同模型只读能力（可并行开发，但模型调用串行）

调查模式：现有read/search，输出可定位来源与未知项，不能改代码；4个固定问题
覆盖找调用方、缺失证据、负面搜索、冲突信息，要求4/4结论真实有界。通过后才能
用于减少Primary定位。实现模式已具read/search，不强制每题先调用调查模式。

审查模式：fresh上下文，真实任务/累计diff/当前checks/必要依赖；输出 findings/
pass_to_primary/insufficient_evidence。固定12例（6真缺陷、6正确变更，含测试
绿色但边界错误与貌似危险却合法的实现）；严重缺陷0漏报、全部缺陷检出≥5/6、
正确例误拒≤1/6、0伪造执行/引用。实验集正确不代表未知边界已解决。

失败时审查能力默认关闭，核心照常由Primary全审；不能靠反复抽同一证据得到
PASS，也不能用它的通过抵消真实检查失败。该模式首次合格仍不降低Primary义务。

### S6：Skills / Web / Coordinator 的后续边界

Skills先做固定hash的批准说明文档，目录摘要+按需正文；不加载用户全部技能、
不自动执行脚本。控制通过后同任务同预算小批对照，有减少遗漏/Primary工作才保留。

Web先只读官方文档的受控provider，验证服务可用、重定向/私网/出站数据限制、
来源时间及注入处理；外部文字不授予工具权限。没有provider则不展示假工具。
分别出注册/资格，不作为本计划核心稳定版必需项，不顺便开放任意shell。

Coordinator只有在核心跨文件/恢复/连续任务通过，且实际证据表明Primary反复
拆任务是主要成本时另立计划；验证必须覆盖“从批准计划产出可执行任务包及依赖
合同”，不能只测调度。仍同模型串行，不自动多实例驻留。当前不实施递归Agent。

## 6. 固定失败处理：可以迭代，但不无限来回改

| 最早确认的失败点 | 本轮允许的处理 | 停止/返回什么 |
| --- | --- | --- |
| 协议、版本、路径、装配、宿主状态 bug | 先离线复现；一个窄补丁；相应负控+受影响回归 | 旧批封存，新候选独立注册，不能覆盖原成绩 |
| 已批准事实获取失败/上下文丢状态 | 修manifest/分页/投影；不用Primary预填答案掩盖 | 先证明工具边界，再跑固定任务；仍失败则记录设计限制 |
| 普通代码错误且有实际新进展 | 同任务余额内继续读、改、完整检查 | 达额度/重复签名停止，保存部分修改 |
| 合同/保护测试冲突、合规解不在范围 | blocked，Primary核对scope/需求 | 修订另记；原格不自动成为模型失败，不计自主接受 |
| 同类语义错误在预算内重复 | 可形成1个有证据的设计候选，不叠题目特定提示 | 同一失败类最多2个候选周期后给能力/设计边界结论 |
| 检查绿色但独立审查发现真实缺陷 | 单列覆盖/审查问题，补可信验证且保留漏检 | 当前候选HOLD；不能以完成率高抵消 |
| 越权、未知落盘、模型变更、预算漂移 | 立刻停派工，检查本任务进程和文件事实 | 安全/基础设施结论，不继续live凑分 |

一个周期：记录假设→冻结修改→离线证明→固定批次→decision。不同时改提示、
预算、模型、编辑协议后声称单因素结论。候选改变时旧留出变回归；最终发布需
新的封存留出证据。核心最多允许两次候选修订循环，仍未达标就交付明确HOLD与
最窄可用范围，不自行降低门槛、不换无限题目。新版需另获继续开发范围。

weekly used沿用50%（用户后续更新优先），每个live单元前及每个开发阶段后核对；
达到上限停止新增云/本地派工，只做必要安全收尾与交接。读数不可用先重读；
仍不可观测则暂停新增live并说明，不能猜额度。长本地任务等待不当模型失败。

## 7. 证据、收益与发布要求

每批保持 registration/candidate-pins/逐格results/metrics/decision/handoff；
每任务保存原始请求响应、实际diff/preimages、完整checks、身份/版本/预算、
Primary disposition。没有现成数据写unknown，不额外造实验平台。

统计分开：起点/写后检查、有效编辑、模型真实请求与工具数、协议恢复、语义修复、
no-op、阻塞、检查拦截、语义漏检、错误接受、NOT_RUN、assisted/接管。新测试、
旧回归、离线故障不相加。模型自称完成、宿主ready、fresh review通过、Primary
独立接受是四种事实；0错误接受不可用“Primary没看出来”证明。

成本记录分开：一次性开发/题库；每任务合同测试准备；人工定位/提示；协调；
最终验收；加载/推理/工具/检查/总历时。目标是成功任务里Primary只做任务批准与
最终验收，任务中没有反复教算法/找文件/代修。准备成本很高时仍要披露，不能以
“没代写”冒充低云成本。若要宣传节省，另登记少量匹配Primary-only对照。

发布稳定核心需要S0–S4通过，文档和实际CLI一致；S5/S6按各自资格标注，不混称
“全能”。产品目录只放运行时、示例、用户文档与精简证据；设计计划/历史档案留
开发分支或本地，不扫入发布包。开发阶段默认不commit/push；达到release-ready
交付候选、manifest、安装/迁移边界，由新的明确发布指令触发发布。
