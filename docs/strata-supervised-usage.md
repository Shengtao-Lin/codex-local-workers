## Primary怎样接手结果

先查看canonical `workflow/runs/<attempt>/result.json`和对应完整交付材料；`status`
只是索引。成功意味着可供Primary审查，接受仍须核实实际源码/diff、configured
checks、fresh Reviewer、保护输入与当前绑定，并按风险做独立关键/整体验收。

独立运行Python验收前，确认目标模块实际从正在审查的项目副本导入。例如使用
相同解释器打印 `module.__file__`，并核对其位于该副本的目标源码下；如项目采用
`src`布局，按项目配置把正确的源码根放在导入路径前，再执行检查。外部私有测试
可能改变pytest的rootdir，复用另一仓库的editable虚拟环境也可能导入旧源码；
仅切换工作目录不一定足够。记录实际解释器、pytest配置、导入路径和失败结果，
发现路径错误时将其归为验收环境错误并纠正，不把错误源码上的通过或失败算作
Worker成绩。当前Strata宿主检查单独设置项目 `src` 和根目录的导入路径；这不替代
对Primary自行运行的检查做同样确认。其他语言或特殊项目按其实际模块机制核对。
同一editable虚拟环境下的实际正负对照见[导入绑定诊断](../benchmarks/work/harness-convergence/strata-import-binding-20261030-1/handoff.md)：
普通调用导入了兄弟仓库，冻结宿主的验证环境导入了隔离副本。该结果仅覆盖测试的
Python包布局，仍须为其他项目核实。

本仓库提供可选的 `tools/check_python_import.py`，可用验收所用解释器执行：

```powershell
python tools/check_python_import.py --python $trialPython --project $projectCopy `
  --module agent_runtime.tools.registry --source-root src
```

将模块名和源码根替换为目标工程实际值；退出码0表示导入文件位于项目目录，1表示
在外部，2表示无法判断或运行失败。`--source-root`只影响这个探针的子进程，后续
pytest或其他检查必须独立采用相同导入环境，再核对其实际路径。该工具会执行普通
Python导入，有导入副作用；只在可信工程使用。它不能验证所有依赖、源码哈希或
测试语义，也不是操作系统隔离和最终验收。

失败先按真实类别处理：错误测试/源码需要原预算内有效修复，非法读取需要合法
窗口，预算停止保留部分成果与失败，scope/合同冲突回Primary解决。配置检查未过、
Reviewer未启动、独立拒绝分别记录；代码通过部分诊断不能当完整链正确。

Primary发现原合同缺陷时，只给有版本绑定的可复现事实；若提供修法或新语义提示，
明确assisted。续作沿原权限/历史/预算，实改后完整检查与fresh审查，不重抽原代码
直到PASS。新边界要求另作合同决定，不悄悄变成修复提示。

事实反馈也要记录介入，既有记录标为assisted的保留原分类。Primary-origin要求
前次canonical fresh Reviewer为无findings的cleanPASS；Reviewer-origin要求逐项
核实canonical findings处置。这是两条不同授权路径，不能互相伪装。
fresh意味着独立上下文和证据快照；Coder与Reviewer仍是同一iq3_s，可能共享语义
盲点。当前完整链必须保留Primary风险审查和独立关键验收。

对于高影响的只读调查，Primary也可选用一次独立、只读的报告自洽性检查：让
模型指出报告把未观察的行为写成确定事实、或正文与未知项冲突的位置，并引用报告
原文。事先为这次检查登记预算和只读范围；它是额外本地调用，不能假装免费或
替代对源码、文档和关键事实的核验。两组已暴露正反对照中，该方法均指出指定
冲突并区分删句版本，但也提出其他需要人判断的措辞问题；这不构成误报率、通用
语义准确率或无人监督接受资格。参见[第一组](../benchmarks/work/harness-convergence/strata-report-consistency-20261030-1/handoff.md)
和[第二组](../benchmarks/work/harness-convergence/strata-sql-report-consistency-20261030-1/handoff.md)。

## 怎样判断是否值得继续用

分别记录一次性安装/实验开发，和每任务重复发生的目标/验收准备、定位、协调、
反馈、最终审查；注明是否给算法、补边界、人工找依赖或代写。能可靠计时就计时，
否则unknown。优先复用可信项目已有检查，只补必要关键验收，不逐任务重建私有
参考实现或实验平台。
