# Supervised local worker scope

Local workers are supervised helpers. The Primary Agent owns task scope,
critical contracts, final acceptance and integration. Apply these routing rules
until the real tool-loop evidence supports a broader scope.

| Work | Current routing |
| --- | --- |
| Sequential async calls, explicit stop sentinel and exception propagation | Coder candidate when protected tests cover order, false-valued results and failures |
| Sum successful results while preserving zero and excluding failed rows | Coder candidate with protected aggregation and non-mutation tests |
| Exact runtime type restrictions, multiple interacting input bounds | Primary-owned implementation; local findings may inform review |
| ASCII-only parsing, canonicalization and cross-file input boundaries | Strong independent acceptance required; delegation remains experimental |
| Transactions, concurrency, security and compatibility changes | Primary classifies the risk and owns the atomic invariant; no scope promotion from small diagnostic successes |

The candidate rows are supported by repeated direct-code tests and four accepted
real Coder-to-Reviewer units (two repetitions per family). Explorer located the
entry/helper/test path successfully twice. Reviewer also passed two clean
sentinel controls and detected two hidden false-value defects. This supports
these small supervised families; reduced total Primary effort remains unmeasured. Coder
uses the configured Qwen model; diagnostic results do not switch the production
model automatically.

Delegate only when a cohesive implementation unit is large enough to justify
coordination. Primary should handle trivial changes directly, even within a
family that has passed these diagnostics.

Explorer must provide real read file/line evidence for a focused investigation.
Its outcome is recorded independently even when Coder later succeeds. Reviewer
must independently review changed source and contract boundaries; passing tests
do not establish its ability to detect untested defects.

Every delegated implementation still needs the configured static checks,
nonzero protected test execution, canonical evidence and independent Reviewer.
Record a Primary accept/rework/replan/takeover decision for each real worker run.
When repeated failures show no progress, retain evidence and take over the unit.

The complete-file normalization candidate remains disabled and limited to
diagnostics. Structured execution counterexamples produced two isolated repair
successes out of ten paired failed samples, without repetition within the same
model/family. Neither change has demonstrated enough transfer to enable it in
the production harness.

Candidate 6 now permits an isolated Coordinator pilot for six registered
supervised families: 14/14 accepted units, Explorer 4/4, eight effective controls
and two Primary-accepted dependency integrations. Historical failures remain HOLD;
transaction/concurrency/security and unfamiliar compatibility scope is not promoted.

Coordinator remains default-off. Reduced Primary work is a separate next-pilot
criterion, not an established benefit or a prerequisite that prevents measuring
it. Synthetic fixtures establish behavior, not real-project cost savings. Exact
evidence: `docs/formal-role-matrix.md`; profile/bounds:
`docs/coordinator-supervised-pilot.md`.

For multi-unit work, state known pending caller behavior and its separate owner
in the unit contract. Reviewer checks the current owned unit, not premature
completion of the whole feature. An unchanged caller's explicitly pending work
is not a current-unit rework finding; a genuine regression caused by the current
unit still must be reported, including defects visible in read-only callers.
Unclear ownership or conflicting cross-unit requirements escalate to Primary.
Unit acceptance never bypasses feature integration or accepts pending units.

The QuixBugs loop/split family remains outside qualified routing. Explicit split
semantics alone did not stabilize its Coder repairs, and a single successful
Primary-guided counterexample repair is not family qualification. Keep its
historical failures separate from any successful restricted Coordinator pilot;
do not treat them as Reviewer startup failures or expand budgets by default.
